{# Base card article body, structured as named Pebble blocks so a theme can restyle one region while inheriting the rest — instead of copy-pasting the whole partial. Expects: card (model, with card.axes: a map of axisName -> {id, label, color}, one entry per axis the card has a value for — resolved from the card's own frontmatter field of the same name, falling back to the folder-cascaded vars entry). Every axis the card belongs to gets its own CSS class on the wrapping
({axisName}-{valueId}) and its own badge in the meta row. The badge keeps the historical "tier-badge" class name literally (not parametrized by axis name) so every existing theme's colour styling for the "tier" axis keeps working unchanged; new axes additionally get a namespaced "axis-badge-{axisName}" hook for themes to style from scratch. Themes override by shipping their own templates/_card-body.html containing {% extends "_card-body-base" %} plus whichever {% block %}s they change; call {{ parent() }} inside an override to keep the base markup and wrap or append to it rather than replacing it outright. The un-themed default at templates/_card-body.html is just {% extends "_card-body-base" %} with no overrides. Named "-base" (not "_card-body") deliberately: theme template loaders are tried before the classpath default, so if this file were named "_card-body" a theme's own same-named override would resolve {% extends %} back to itself and recurse. Keep any future shared base template under a distinct "-base" name for the same reason. #}
