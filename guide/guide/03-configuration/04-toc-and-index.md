# TOC and Index

A book can open with a printed table of contents and close with a
back-of-book index — both carrying **real page numbers**, resolved against
the finished PDF's own pagination. This page is a live demo of each: the
contents page after this guide's cover and the index before its end were
generated by the two flags below.

## Turning them on

Both are off by default and switch on in the root `paperband.yaml`:

```yaml
vars:
  toc: true      # contents page after the cover / front matter
  index: true    # index page after the last card
```

A POM-declared book says the same with `<toc>true</toc>` and
`<index>true</index>` inside `<book>`, or through `<book><vars>`. The
headings default to *Contents* and *Index*; override them with
`vars.tocTitle` and `vars.indexTitle`.

The contents page lists every divider and card in the exact order the PDF
assembles them — axis or section dividers first, their cards indented one
step beneath — each entry linking to its page. Books without dividers get a
flat list. The index is built from card frontmatter:

```yaml
---
id: install
index: [installation, chromium]
---
```

Each `index:` term (a yaml list, or one comma-separated string) points at
the page of every card that declares it, grouped under first letters and
sorted case-insensitively. A book that enables `index: true` but declares no
terms renders no index page at all rather than an empty one.

## How the page numbers work

Page numbers don't exist when the HTML is written — Chromium decides
pagination when it prints the PDF. So the build renders twice: the first
pass renders every page number as a fixed-width placeholder, the real
numbers are read back from that PDF's named destinations (the same data
`mvn paperband:pages` reports), and a second pass renders the book again
with the numbers filled in. The substitution changes only the text inside
each placeholder, so pagination cannot shift between passes and the printed
numbers are exact. The build logs the second pass:

```
[INFO] Resolved 42 page reference(s) (toc/index) in a second render pass
```

The extra render only happens when at least one placeholder is present —
books without `toc`/`index` build in one pass exactly as before.

## Styling

Both pages take as many sheets as they need and inherit the theme's colours.
Restyle them from the book's CSS chain or a theme via `.book-toc` and
`.book-index` — entries expose `toc-kind-divider`/`toc-kind-card` and
`toc-depth-0`/`toc-depth-1` classes, the dotted leader is `.toc-leader`, and
the index's two-column layout is a `column-count` on `.index-groups`. For a
different structure entirely, override the `_book-toc.html` or
`_book-index.html` template from `layouts/` like any other bundled template.

## Watch Out

**The contents and index are PDF concepts.** The static site already has an
index page and per-card navigation, so the `site` goal ignores both flags —
there are no page numbers on the web.

**A `?` where a number should be means the anchor didn't exist** in the
first pass — the build warns naming it. The bundled templates only reference
anchors they just generated, so a `?` normally points at a custom template
referencing a card id that isn't in the book.

## Check

Enable `toc: true`, build, and run `mvn paperband:pages` on the PDF: the
`(contents)` row shows where the TOC landed, and the numbers printed on that
page match the report's START column exactly — they come from the same named
destinations.
