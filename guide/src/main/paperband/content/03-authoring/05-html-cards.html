This page is an .html card. The <head> is the frontmatter: <title> names the card the way title: does, and each <meta name content> becomes a frontmatter field, so axis values, index: terms and sort: fields all work. Numeric and boolean content is typed the way yaml would type it — content="1" sorts and groups like tier: 1.

<head>
  <title>Alpha Service</title>
  <meta name="tier" content="1">
  <meta name="index" content="alpha, services">
</head>

Where an HTML card is allowed

Whether an .html file is a card depends on where it is:

  • Walked books: an .html under the content/ wrapper is a card, because everything there is content. A book without the wrapper keeps markdown-only discovery.
  • POM-declared books: the include pattern itself must end in .html (pages/*.html, interstitial.html). A bare sweep never claims one, and warns when it would have.

Same pipeline, same rules

The body goes through the same pipeline as a markdown card's rendered body: headings split it into blocks (this h2 opened one), the content policy strips presentation the theme should own, and the card gets a TOC entry, section membership and a site page like any other. A card with no <title> takes its name from the first h1, which is then consumed, as in markdown.

Pebble works here too: the book's version is {{ vars.version }}. Where markdown masks fences and backticks, an HTML card masks <pre> blocks, <code> spans and comments, so the literal {{ vars.version }} in this sentence is not evaluated.

Watch Out

An HTML card is still content: the content policy applies unchanged, so inline style= and <style> blocks are stripped under the default clean policy.
